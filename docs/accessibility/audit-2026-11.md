# Accessibility audit, November 2026 (milestone 10)

Target: WCAG 2.2 level AA. Method: axe-core 4 (rules tagged wcag2a, wcag2aa, wcag21a, wcag21aa,
wcag22aa) on 17 pages at 1280 px, signed out and signed in with a partner and real content
(`eng/accessibility/axe-audit.js`); keyboard checks with Playwright; phone-width (390 px)
screenshots of every flow from milestones 04 to 09.

## Automated results

| Finding | WCAG | Pages | Triage | Status |
|---------|------|-------|--------|--------|
| Status colours (alert text, text buttons) below 4.5:1 | 1.4.3 | Home, Support, Workspace, Safety, Personal data | Darker info, success, warning and error colours in a custom theme | Fixed |
| Links in text distinguished by colour only | 1.4.1 | Support, Privacy | Links inside text are always underlined | Fixed |
| Interactive pages had no `<title>` | 2.4.2 | 9 signed-in pages | Interactive pages render without prerendering, so their own title never reached the page head; the layout now sets a title per route | Fixed |
| `/Account/Manage` failed with a server error for signed-in users | (functional) | Account pages | The "Messages (n)" link and the account page ran database queries at the same time on one connection; the link now uses its own scope. Interactive pages also get their own scope (`ScopedPage`) | Fixed |
| "Delete" button on the personal data page below 4.5:1 (link colour overrode white text) | 1.4.3 | Personal data | Darker red | Fixed |

After the fixes, axe reports **0 violations on all 17 pages**. Four results are "incomplete"
(axe couldn't decide), and they're triaged for the manual pass below:

| Incomplete | Pages | Triage |
|------------|-------|--------|
| Contrast of empty text fields (needs a value to measure) | Received message, Write a message | Low: same MudBlazor outlined field that passes elsewhere with text in it; confirm in manual pass |
| Contrast where an element overlaps the background | Pace | Low: confirm in manual pass |
| `aria-required-children` on a MudBlazor list | Exercises | Medium: check list semantics with a screen reader; replace with plain markup if announced wrongly |

## Keyboard
- A "Skip to main content" link is the first Tab stop on every page and moves focus to `<main>`
  (2.4.1). Verified with Playwright.
- Visible focus outlines on links, buttons and inputs, including the app bar and "Leave quickly"
  (2.4.7, 2.4.11).
- Exercises move focus to each new step's heading (since milestone 05).
- Motion is reduced when the system asks for it.

## Milestone 11 recheck (2026-11-09)
- axe-core on 21 pages (adds `/privacy-notice`, `/terms`, `/pilot`, `/feedback`): two new issues
  found and fixed, then 0 violations. Links inside MudBlazor text weren't underlined
  (link-in-text-block, 1.4.1), and footer links were under the 24px target size (2.5.8).
- Reflow at 320 CSS pixels (1.4.10, equivalent to 400% zoom on a 1280px screen): no page scrolls
  sideways, across 20 pages including admin (`eng/accessibility/reflow-check.js`).
- The pilot flow was also walked in the production-configured rehearsal with no CSP errors.
